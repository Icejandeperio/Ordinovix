# ADR-0002: Backend stack, naming conventions, and the cloud boundary

**Status:** Accepted · **Date:** 2026-10-28 · **Owner:** Icejan (human-owned; agents may not edit)
**Builds on:** ADR-0001 (gate, ratchet, pre-approved dependencies) and `docs/backend/BACKEND_PLAN.md` (U19)

## Context

The frontend phase (U00–U20) is merged with no known failures. The owner decided to build the full backend before
the MVP is shown to the client. Claude Code builds it autonomously, so three things must be fixed in advance:
which packages it may install, which names and bindings CI deploys against, and where the line sits between
local work (agent) and the live Cloudflare and Google accounts (owner and CI only).

## Decision

### 1. Stack (as in BACKEND_PLAN.md section 1)

| Concern | Choice | Version verified 2026-10-28 | Licence |
|---|---|---|---|
| API on Workers | `hono` | 4.13.13 | MIT |
| Database | Cloudflare D1 with `drizzle-orm` / `drizzle-kit` | 0.45.4 / 0.31.11 | Apache-2.0 / MIT |
| Auth | `better-auth` (Drizzle adapter, Google provider only) | 1.7.12 | MIT |
| Dev and build | `@cloudflare/vite-plugin` with `wrangler` | 1.64.0 / 4.151.3 | MIT / MIT OR Apache-2.0 |
| Worker types | `@cloudflare/workers-types` (optional; `wrangler types` preferred) | 5.20261019.1 | MIT OR Apache-2.0 |
| Web Push | `@pushforge/builder` (zero dependencies, Web Crypto, built for Workers) | 2.0.5 | MIT |
| Files | Cloudflare R2 through a Worker binding; bucket never public | n/a | n/a |

Install rule unchanged from ADR-0001: the newest release that is at least 7 days old at install time, same major
as above, `--save-exact`. `wrangler` 4.151 requires Node 22 or newer (CI uses 22, the laptop 24).

### 2. Testing without a Vitest major upgrade

`@cloudflare/vitest-pool-workers` 0.23 requires Vitest 4; the repo is on Vitest 3 and a major upgrade is T3.
Worker code is therefore tested under the existing Vitest with `getPlatformProxy()` from `wrangler`, which provides
local D1 and R2 emulation (Miniflare), and Hono's `app.request()`. Upgrading to Vitest 4 and the workers pool is a
later, separate owner decision.

### 3. Conventions CI depends on (do not change without a new ADR)

| Item | Value |
|---|---|
| Config file | `wrangler.jsonc` at the repo root; `main` is `worker/index.ts` |
| Static assets | Served by the same Worker: `assets.not_found_handling: "single-page-application"`, `assets.run_worker_first: ["/api/*"]` |
| API base | `/api/v1/*`; Better Auth under `/api/auth/*` (Google callback `/api/auth/callback/google`) |
| Environments | top level = local development; `env.preview`; `env.production` |
| Worker names | `ordinovix-preview` (preview), `ordinovix` (production) on `*.workers.dev`; no custom domain |
| D1 binding `DB` | databases `ordinovix-preview` and `ordinovix`; real ids written by the owner's setup script |
| R2 binding `FILES` | buckets `ordinovix-preview-files` and `ordinovix-files` |
| Variable `APP_ENV` | `local`, `preview`, `production` |
| Migrations | `migrations/` (wrangler default), generated by `drizzle-kit generate` from `worker/db/schema.ts`; a migration that is on `main` is never edited, only followed by a new one |
| Secrets | `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `FILE_URL_SIGNING_KEY`, `TIN_ENCRYPTION_KEY` |
| Local secrets | `.dev.vars` (gitignored, generated with random values by a script; agents never read it) |
| Build for an environment | `CLOUDFLARE_ENV=<env> npm run build`, then `npx wrangler deploy` (CI only) |
| Preview seed | `npm run --silent db:seed-sql` prints idempotent SQL for the Demo organization (same ids as the mock seed) |
| Dev sign-in | A persona sign-in route exists only when `APP_ENV=local` and `DEV_AUTH=1`; it returns 404 in preview and production |

### 4. The cloud boundary

| Who | May do |
|---|---|
| Claude Code (guard-enforced) | Everything local: `wrangler dev`, `wrangler types`, `wrangler check`, `wrangler d1 migrations create`, `wrangler d1 migrations apply/list --local`, `wrangler d1 execute --local`, `wrangler r2 object ... --local`, `drizzle-kit generate/check/up/export`. Read-only checks of the deployed preview over HTTPS. |
| CI (`.github/workflows/deploy-*.yml`) | Apply remote migrations and deploy: preview automatically after `verify` passes on `main`; production only by manual dispatch, gated by the `production` environment's required reviewer (the owner). Weekly D1 export of production into R2. |
| Owner | Create the Cloudflare and Google accounts, the OAuth client, D1 databases, R2 buckets, secrets, the Cloudflare API token, GitHub secrets and the `production` environment, using `scripts/setup-cloudflare.mjs` (written by U30). |

The laptop keeps no Cloudflare credentials: the setup script ends with `wrangler logout`. Even if a local guard were
bypassed, nothing on the laptop could deploy or read live data.

Never in a workflow: uploading a database export or any client data as a GitHub artifact. This repository is public.

### 5. Accounts and handover

Until the client accepts the MVP, the Cloudflare and Google accounts belong to the owner (Icejan). Preview holds the
Demo organization only. Production stays empty until go-live; at handover it is either redeployed to an account the
client owns (no data to move) or kept with the client added as an account member.

### 6. Review rule (permanent)

The verifier blocks only on (a) an acceptance criterion of the unit without evidence, or (b) a regression: something
that works on `main` and no longer does. Every other finding goes to `docs/state/QUEUE.md` under Proposals, or to the
unit's follow-up if one exists, and does not block. This replaces the open-ended "try to refute done" standard that
kept U07 blocked through five rounds.

### 7. Guard changes in this decision

- Local-only allowlists for `wrangler` and `drizzle-kit` (section 4); everything else with those tools is blocked.
- `npm run <script>` is checked against the command the script runs, so a deploy cannot hide in `package.json`.
- Only acceptance tests committed on `origin/main` are read-only. Drafts on a unit branch can be fixed or deleted,
  which ends the stray-draft problem (U02, U06, U10–U13).
- `.dev.vars` is treated like `.env`.

## Deferred

Vitest 4 with `@cloudflare/vitest-pool-workers`; a custom domain; an email provider (needs a domain; phone push is used
instead); automatic retention deletion (off until the client chooses a period).

## Consequences

- The agent can build and test the whole backend locally with no account. Owner actions are needed once, at U30.
- `.github/**` and this ADR fix the deploy contract; changing names or bindings needs the owner.
- Production deploys are always a human decision.
