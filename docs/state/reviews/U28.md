## Advisory
1. The "removes the object again when the database batch fails" test is vacuous. Its Proxy makes the first `DB.batch` call fail, which is the read-side load batch (worker/db/load.ts, 37 statements), so the request fails before any R2 put. With `await files.discard()` removed the test still passes (verified). In a scratch test that fails only the write batch, removing discard() leaves the orphan object and fails, so the code is correct but untested. Proposal: make the Proxy fail only when a statement list contains `INSERT INTO documents`.
2. The `onlyIf: { etagDoesNotMatch: '*' }` no-overwrite option has no test: removing it leaves all 23 tests green. A scratch test (put twice with the same key, expect the second to throw and the first bytes to remain) passes with it and fails without it. Proposal: add that as a small test in documents.test.ts or worker/files/store.test.ts.
3. The 15 MB check exists both in the route (raw.size) and as a content-length precheck; only the route one is red-on-removal covered (the precheck needs a request over about 16 MB with a real header). Fine as defense in depth.
4. Whole-file buffering (arrayBuffer) of up to 15 MB plus the SHA-256 happens in the Worker; fine within Workers limits, but note it for the preview deploy.
5. docs: BACKEND_PLAN 7a still lists the retention job as a separate item; the daily `0 19 * * *` cron should be mentioned when U29 adds the reminder crons.
