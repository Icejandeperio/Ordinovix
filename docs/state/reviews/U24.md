### Red-on-removal reasoning (no source modified)
- requireMembership removed (or its `throw AccessPendingError`): `actor` would be undefined, requireActive would throw a TypeError -> 500; "no membership: 403 ACCESS_PENDING", the soft-deleted case and the unverified/taken cases fail.
- requireActive removed: revoked helper "mem-carl" would get 200 from session/me; test "revoked membership: 403 FORBIDDEN" fails.
- Verified-email condition (`user.emailVerified ? ... : sql\`0\``) removed: the unverified address would match by email and link; "does not link on an unverified email" (cookieFor writes email_verified=0, which the real Better Auth session reads back) expects ACCESS_PENDING and user_id still NULL, so it fails.
- "Never take over a linked entry" (`claim = rows.find(r => r.userId === null)`, plus `AND user_id IS NULL` in the UPDATE): if it were relaxed to any matching row, `ba-second` would claim `mem-taken`; "never takes over an entry that is already linked to somebody else" fails (ACCESS_PENDING and user_id = user-first asserted).
- Dev gate (`devAuthEnabled`) removed or loosened to either condition: the five 404 cases (preview/production with DEV_AUTH=1, preview/production, local without DEV_AUTH) fail.
